# Feature: API Key Validation on Login

## What This Does

Before starting a focus session, the extension now **validates your API key** with Anthropic to ensure it's correct. This prevents:

- Starting sessions with invalid keys
- Discovering API key issues 15 minutes into a session
- Confusion about why AI features aren't working

## User Experience

### Before (no validation)

```
User enters API key
↓
Clicks "Start Focus Session"
↓
Session starts immediately
↓
15 minutes later... AI check fails ❌
User has no idea why
```

### After (with validation)

```
User enters API key
↓
Clicks "Start Focus Session"
↓
Button shows: "Validating API key..."
↓
✅ Valid → Session starts
❌ Invalid → Clear error message, can fix immediately
```

## How It Works

### 1. Validation Function (background.js)

```javascript
async function validateApiKey(apiKey) {
  // Makes minimal API call (costs < $0.001)
  const response = await fetch(ANTHROPIC_API_ENDPOINT, {
    method: 'POST',
    headers: {
      'x-api-key': apiKey,
      // ...
    },
    body: JSON.stringify({
      model: 'claude-sonnet-4-20250514',
      max_tokens: 10, // Minimal to keep cost down
      messages: [{ role: 'user', content: 'Hi' }],
    }),
  });

  // Check response status
  if (response.ok) {
    return { valid: true };
  } else if (response.status === 401) {
    return { valid: false, error: 'Invalid API key...' };
  } else if (response.status === 429) {
    return { valid: false, error: 'Rate limit exceeded...' };
  }
  // ... handle other errors
}
```

### 2. Updated Start Session Flow (popup.js)

```javascript
async function startSession() {
  // Get values
  const purpose = document.getElementById('purposeInput').value.trim();
  const apiKey = document.getElementById('apiKeyInput').value.trim();

  // Show loading state
  startBtn.disabled = true;
  startBtn.textContent = 'Validating API key...';

  // Validate key
  const validation = await chrome.runtime.sendMessage({
    action: 'validateApiKey',
    apiKey
  });

  if (!validation.valid) {
    // Show error and stop
    alert(`API Key Error: ${validation.error}`);
    startBtn.disabled = false;
    return;
  }

  // Key is valid, proceed with session
  await chrome.storage.local.set({ apiKey });
  await chrome.runtime.sendMessage({
    action: 'startSession',
    purpose
  });

  showActiveView(...);
}
```

### 3. Visual Feedback (popup.css)

Button states:

- **Normal**: Blue, clickable
- **Validating**: Gray, disabled, shows "Validating API key..."
- **Error**: Re-enables, shows alert with specific error

## Error Messages

The validation catches different error types:

### Invalid API Key (401)

```
"Invalid API key. Please check your key and try again."
```

**Cause**: Key is wrong, expired, or doesn't exist

### Rate Limited (429)

```
"Rate limit exceeded. Please wait a moment and try again."
```

**Cause**: Too many requests to API, need to wait

### Network Error

```
"Network error. Please check your connection and try again."
```

**Cause**: No internet, firewall, or connection issue

### Other API Errors

```
"API error (500). Please try again."
```

**Cause**: Anthropic server issue or other problem

## Cost Impact

**Validation cost per attempt:**

- 1 API call with 10 max_tokens
- Cost: **< $0.001** (basically free)
- Only happens once at session start

**Comparison:**

- Validation: $0.0001 per attempt

So the validation is **negligible cost** for huge UX improvement.

## Debugging

### Check console logs:

```
chrome://extensions/ → service worker → Console
```

Look for:

- "Validating API key..."
- "API key validated successfully"
- Or: "API key validation failed: [reason]"

### Check what's sent to API:

In service worker console:

```javascript
// The validation call should look like this
{
  model: "claude-sonnet-4-20250514",
  max_tokens: 10,
  messages: [{ role: "user", content: "Hi" }]
}
```

### Common issues:

**"Invalid API key" but key is correct:**

- Check for trailing spaces (we use `.trim()` but double check)
- Verify key format starts with `sk-ant-`
- Check Anthropic console for key status

**Validation takes forever:**

- Network issue or firewall blocking Anthropic
- Check browser network tab for failed requests

**Button stays disabled:**

- JavaScript error during validation
- Check popup console for errors

## Edge Cases Handled

- ✅ Empty API key (caught before validation)
- ✅ Malformed API key (401 from API)
- ✅ Valid format but wrong key (401 from API)
- ✅ Rate limit exceeded (429 from API)
- ✅ Network timeout or connection error
- ✅ User clicks button multiple times (disabled prevents)
- ✅ API returns unexpected status code

## Security Notes

- API key is sent to Anthropic only, never to any other server
- Validation call is minimal (10 tokens) to minimize exposure
- Key is stored locally in chrome.storage.local (encrypted by Chrome)
- Key is never logged to console (only validation result)
