# Bug Fix #3: API Key Getting Doubled

## The Problem

After completing a session and returning to the start screen, the API key input field showed the key **doubled**:

- Original: `sk-ant-abc123`
- Became: `sk-ant-abc123sk-ant-abc123`

This made the API key invalid and broke future sessions.

## Root Causes

Found **3 potential causes** that could contribute to this issue:

### 1. Browser Form Caching

Chrome automatically saves and restores form input values when the popup reopens. This can cause the field to have an old value before our code runs.

### 2. loadApiKey() Not Clearing First

```javascript
// OLD CODE (buggy)
async function loadApiKey() {
  const { apiKey } = await chrome.storage.local.get('apiKey');
  if (apiKey) {
    document.getElementById('apiKeyInput').value = apiKey; // Sets value without clearing first
  }
}
```

**Problem:** If the input field already had a value (from browser cache or previous state), setting `.value` should replace it, but browser quirks or timing issues could cause problems.

### 3. showSetupView() Reloading Key Without Clearing

```javascript
// OLD CODE (partially buggy)
function showSetupView() {
  // ... show/hide views ...
  document.getElementById('purposeInput').value = ''; // Clears purpose
  // Does NOT clear or reload API key!
}
```

**Problem:** When returning to setup view, the API key field kept its old value, and then potentially got reloaded, causing duplication.

## The Fixes

### Fix 1: Always Clear Field Before Setting Value

**popup.js - Updated loadApiKey():**

```javascript
async function loadApiKey() {
  const { apiKey } = await chrome.storage.local.get('apiKey');
  const apiKeyInput = document.getElementById('apiKeyInput');

  // CRITICAL: Always clear the field first to prevent duplication
  apiKeyInput.value = '';

  if (apiKey) {
    apiKeyInput.value = apiKey;
  }
}
```

**What this does:**

- Explicitly clears the field to empty string first
- Then sets the value from storage
- Prevents any browser caching or state issues

### Fix 2: Reload API Key When Showing Setup View

**popup.js - Updated showSetupView():**

```javascript
function showSetupView() {
  document.getElementById('setupView').style.display = 'block';
  document.getElementById('activeView').style.display = 'none';
  document.getElementById('summaryView').style.display = 'none';

  // Clear purpose input
  document.getElementById('purposeInput').value = '';

  // Reload API key fresh from storage to avoid duplication
  loadApiKey();
}
```

**What this does:**

- When returning to setup screen, reloads the API key
- loadApiKey() now clears first, so this ensures clean state
- Purpose is cleared since it should be fresh each session

### Fix 3: Disable Browser Autocomplete

**popup.html - Updated inputs:**

```html
<!-- API Key Input -->
<input
  type="password"
  id="apiKeyInput"
  placeholder="sk-ant-..."
  autocomplete="off"
/>

<!-- Purpose Input -->
<textarea
  id="purposeInput"
  placeholder="e.g., Research React frameworks"
  rows="3"
  autocomplete="off"
></textarea>
```

**What this does:**

- `autocomplete="off"` tells browser not to cache/restore these fields
- Prevents browser from interfering with our manual value management
- Both fields now have this for consistency

## How the Bug Likely Happened

**Suspected scenario:**

```
1. User enters API key: "sk-ant-123"
2. Browser caches this value
3. Session ends, popup closes
4. User reopens popup
5. Browser restores cached value: apiKeyInput.value = "sk-ant-123"
6. DOMContentLoaded runs → loadApiKey() executes
7. loadApiKey() sets value: apiKeyInput.value = "sk-ant-123"
8. Due to timing/browser quirk, this somehow doubles it
9. Result: "sk-ant-123sk-ant-123"
```

**OR:**

```
1. Session ends, user clicks "Start New Session"
2. showSetupView() is called
3. API key field STILL has old value
4. Some event causes popup to reinitialize
5. loadApiKey() runs again on existing value
6. Duplication occurs
```
